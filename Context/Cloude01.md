# Передача контекста: проект «Creatures с роботами-девочками»

Спасибо, мне тоже было очень приятно. Ниже всё, что нужно преемнику, чтобы продолжить без потерь.

---

## 1. Кто пользователь и как с ним работать

- Пишет по-русски, неформально. Решения по дизайну принимает он сам. Наша задача — предлагать варианты, объяснять последствия и писать код.
- Код вносит **агент Copilot (режим Agent в VS Code)**. Задания пишутся **для агента**, без объяснений «для человека» («мясной буфер» — это сам пользователь, он так себя называет).
- Если пользователь просит «кратко», отвечать кратко и пошагово: что нажать и где.
- Ценит **последовательность терминов**: однажды он поправил смешение понятий, и с тех пор терминология из раздела 3 обязательна.
- Строит игру, а не функциональную модель мозга. Некоторые элементы могут быть «просто для прикола».

## 2. Концепция и принятые решения

- Аналог Creatures: 2–3 рободевочки, которые взаимодействуют между собой. Аугментации, ragdoll, модульный мозг с горячей заменой чипов.
- **2D, вид сбоку.** Графика без спрайтов: `_Draw`, капсулы, визор с глазами.
- **Godot 4 .NET, C#.** Важна стабильность.
- **Обучение настоящее, без имитации.** Моторика учится «во сне» эволюционными стратегиями (ES) в ускоренной симуляции. Решения учатся днём (план: SARSA(λ)).
- **Иммерсивность:** чипы физически вынимаются, голова открывается, время не останавливается (физический UI пока не сделан).
- **Вмешаться можно во всё, включая прошивку.** Жёстко зашита только физика тела (железо).
- **Моторная кора — один чип с секторами протоколов**, а не банк отдельных чипов.
- **Драйвы — смесь химии и чисел.** Внутри течёт жидкость: охлаждение, транспорт и «гормоны», которые регулируют поведение.
- **Приводы электрические.** Абстрактные катушки деградируют: сопротивление растёт от перегрева и механического износа.
- **Упоры суставов изнашиваются, становятся хрупкими и ломаются.** Дальше сустав может проворачиваться: стирается изоляция, рвутся трубки хладагента и кабели, случаются КЗ, течёт хладагент. Это сделано, у износа есть режимы Off / Frozen / Live.
- **Боль трёх уровней:** дискомфорт, боль, острая. Сделано последним шагом.

## 3. Терминология (обязательная)

| Термин | Значение |
|---|---|
| Доля (lobe) | Функциональный отдел с постоянным контрактом входов и выходов |
| Слот | Разъём доли |
| Чип | Сменная начинка слота: ROM, пустой, обученный, повреждённый, сгоревший |
| Протокол | Программа поведения внутри доли |
| Шина | Именованные каналы `float[]` в `Brain.Bus` |

- STAND, RECOVER, GETUP, WALK — **протоколы моторной коры**, то есть сектора чипа.
- **BRACE** (сгруппироваться) — протокол **доли рефлексов**, запускается сигналом угрозы `threat`. Пока не сделан.
- Гироскоп — **аугментация**, а не часть мозга.

## 4. Архитектура (текущее состояние)

**Физика и масштаб:** 240 Гц, 32 итерации решателя, `max_physics_steps_per_frame=8`. 1 м = 100 px, гравитация 980. Рост девочки около 168 px, масса 48 кг. `RefHeight=100`, `Mgh = M·g·100`.

**Тело:** 13 частей: `pelvis, waist, chest, head` и `thigh/shin/foot/uarm/farm` с суффиксами `_f` (дальняя) и `_n` (ближняя). 13 суставов: `lumbar, thoracic, neck, hip, knee, ankle, shoulder, elbow` (×2 там, где парные). Угол сустава = ребёнок − родитель, при сборке все углы 0, персонаж смотрит в +x.

**Слои коллизий:** 1 — мир, 2–4 — девочки (собственные части тела друг с другом не сталкиваются), 6 — клоны во сне.

**Порядок такта** (`Ragdoll._PhysicsProcess`):
```
ReadSensors → Dur.Tick → Dur.Sense (мозг видит датчики с поломками) → Nerves.Tick
→ Brain.Tick: VESTIBULAR, ARBITER, MOTOR, REFLEX → Compose → FIRMWARE
→ DriveCoils → ApplyStops → ApplyGyro → UpdateVisuals
```

**Сборка команды:** `target = motor + Δreflex·boot`, `stiff = max(motor·boot·(1−inhibit), reflex·boot)`. Затем FIRMWARE: stable PD → команда тока, лимит тока, тепловой дерейт выше 85 °C, доводчик у края хода, тонус 0,02.

**Модель катушки:**

$$R=(1+\alpha(T-T_{amb}))(1+D),\quad i_{max}=V/R,\quad \tau=i\,\tau_{ном},\quad \dot T=\frac{k\,i^2R-c\,(T-T_{amb})}{\tau_{th}}$$

Здесь $c$ — охлаждение (снижается при порванной трубке). $D$ растёт от перегрева выше 120 °C и от $|i\,\omega|$.

**Слоты** (частота, ROM-чипы):

| Слот | Частота | ROM-чипы |
|---|---|---|
| FIRMWARE | 240 | `FW 1.1`, `FW OC!` (разгон, без защиты и без доводчика) |
| VESTIBULAR | 120 | `VEST ROM`, `VEST б/у` (дрейф показаний). Даёт `vest.balance`: наклоны, центр масс, ξ (capture point), запас до края опоры, «лежит» |
| REFLEX | 120 | `REFLEX ROM 1.2`, `x2.5`. Баланс на голеностопах, бёдрах и позвоночнике (только на ногах), отдёргивание по `pain.limit` (всегда), при острой боли — оцепенение и подавление моторики |
| ARBITER | 10 | `ARB ROM` (автомат STAND ↔ RECOVER по запасу ξ, GETUP лёжа), `ARB LOCK STAND`. Без чипа вектор протоколов `p` застывает |
| MOTOR | 30 | `MOTOR ROM` (позы по секторам), `MOTOR NN` (из файла), `BLANK` |

**NeuralMotorChip:** вход 47 = углы и скорости (26) + `vest.balance` (14) + `pain.total` (3) + `cmd` (4). Сеть 32 → 32, выход 26, 8 секторов.

$$h_1=\tanh(W_1x+b_1+Ep)\odot(1+Gp),\quad h_2=\tanh(W_2h_1+b_2),\quad o=W_3h_2+b_3+Op$$

Выход `target = tanh(o)`, растянутый в диапазон сустава; `stiff = sigmoid(o − 2,5)`. У каждого сектора хранятся `Maturity` и `SectorGen`. `Mask(sector, shared)` даёт маску обучения: свои сектора 1, чужие 0, общие веса `1/(1 + 2·Σ зрелости остальных)`. Файл `user://chips/motor_nn.chip`, формат v2, запись атомарная через `.tmp`, `IoHash` — FNV-1a.

**Сон (`Dream.cs`):** ES (16 пар, σ=0,04, lr=0,03, Adam, ранги, маска `Scale`). Около 25% пар повторяют зрелые сектора. Экзаменационные клоны работают с текущими весами θ; лучший чип сохраняется по итогу экзамена плюс бонус учебной программы. Травмы из игры передаются через `DreamJob.Damage` в режиме Frozen. Задачи — `IDreamTask`: `StandTask` (ветер, поза, энергия, боль), `RecoverTask` (толчок, реальный `ArbiterRom`, сложность через `ICurriculum`).

## 5. Грабли, на которые уже наступили (не повторять)

1. **Встроенные пределы `PinJoint2D` не подходят:** они считают угол по линии между центрами тел в мировых координатах. Пределы реализованы в коде.
2. **В stable PD $I_{eff}$ брать только по двум соседним телам.** Поддерево плюс множитель «на земле» дали NaN и взрыв (предупреждение `normalize`).
3. **На 120 Гц голеностопу не хватало жёсткости, она падала вперёд.** Помог переход на 240 Гц и `BalanceGain` 4.
4. **Обёртка угла в ±π взрывала плечо** (предел −3,0 рядом с −π). Угол теперь **непрерывный**, через накопление приращений. Жёсткость упора ограничена (`≤0,3·I/dt²`, демпфирование `≤0,6·I/dt`), упор только толкает.
5. **Награда:** толчок в каждом эпизоде научил постоянно группироваться. Из этого правило: **протокол учится только в своей ситуации и включается арбитром.** Хаки награды («широкая стойка», «семенит ногами») лечатся штрафами за энергию и скольжение. Лучший чип выбирается по фиксированному экзамену, а не по одному шумному эпизоду.
6. **Боль «по умолчанию»:** колено в стойке (0,10 рад) попадало в зону боли 0,15. Теперь зона комфорта 0,05 и привыкание.
7. **Без моторной коры упоры ломались,** потому что их никто не демпфировал. Добавлен доводчик в прошивке и отдёргивание в рефлексах.
8. **Клоны во сне не были видны.** После диагностики (пол, камера за экзаменуемой, счётчики) всё заработало. Точная причина не выяснена.
9. `string.GetHashCode` нестабилен между запусками, поэтому используется FNV-1a. В headless нужен `OS.LowProcessorUsageModeSleepUsec = 0`.
10. **Ответы дважды обрывались из-за длины** (один раз посреди `Dream.cs`). См. раздел 8.

## 7. Дорожная карта

1. **Проверить RECOVER:** растёт ли «толчок N%» выше 50–60% (это значит, что появился шаг) и не проседает ли `replay`. Если шаг не учится, добавить CPG или эталон шага, удлинить эпизод, ослабить штраф запаса ξ.
2. Рефлекс FALL (руки вперёд, голову к груди) и сектор **GETUP**.
3. **Физический интерфейс мозга:** голова на шарнире, чипы — `RigidBody2D` на пружине к курсору, слоты — `Area2D` с магнитом, текстура чипа из весов.
4. **Жидкость v1:** 3 отсека (голова, конечности, ядро), насос, радиатор, фильтр. Вещества: Форсаж, Тишь, Искра, Ржа, Дрёма, Связь, Шлак, Смазка, Наниты. Излучатели, рецепторы и реакции задаются данными (как в Creatures). Хладагент заменяет `Ambient`, батарея задаёт `V`. Боль становится излучателем Форсажа. Во сне химия рандомизируется.
5. Доля драйвов, сенсорика (зрение, осязание, угроза → BRACE), доля решений (SARSA(λ), признаки «драйв × объект»).
6. Сектор **WALK** (вероятно, через CPG).
7. Дневное обучение: быстрые веса $F$, кукловодство, дистилляция по кабелю. Консолидация во сне, давление Дрёмы.
8. Вторая и третья девочки: социальные драйвы, захваты рукой (суставы, которые рвутся), протоязык.
9. Аугментации со схемой тела (смена `IoHash` требует переобучения). Коммутационная панель шины (щуп и перемычки), чипы «для прикола», повреждённые чипы.

## 8. Мой рабочий процесс и пожелания преемнику

**Как я работал.** Код я **ни разу не запускал**: в песочнице нет Godot, а сеть зависала. Я писал код целиком, агент его вносил, пользователь присылал симптомы, я ставил диагноз по чтению кода. Задания для агента строил так:
- нумерованные операции `CREATE`, `REPLACE`, `EDIT`;
- для `EDIT` — точный якорь, который должен встретиться ровно один раз, иначе агент останавливается;
- в конце `dotnet build`, проверки grep и **отчёт по шаблону**;
- для пользователя — отдельная короткая часть «что нажать» и таблицы «симптом → какую ручку крутить».

**Где я ошибался и что стоит изменить:**
1. **Слишком длинные ответы обрываются.** Держите задание для агента в пределах ~500–600 строк кода. Если больше, делите на части «1/2, 2/2» и заранее пишите, что будет продолжение.
2. **Числа ожиданий я называл слишком уверенно.** Явно помечайте их как оценку.
3. **Ошибки в награде были мои.** Сначала проектируйте учебную программу на бумаге: в какой ситуации включается протокол, что поощряется, какие хаки возможны. Только потом пишите код.
4. **Замкните цикл тестов.** Попросите пользователя добавить `Godot_*_console.exe` в PATH, чтобы агент сам запускал headless.
5. **Сделайте сцену smoke-теста** (`Test.tscn`): поставить девочку, 10 с стойки, толчок, по очереди вынуть каждый слот, падение без рефлексов, проверка на NaN, вывод метрик. Агент запускает её после каждого изменения и прикладывает вывод к отчёту.
6. **Попросите агента вести в репозитории** `ARCHITECTURE.md` (этот документ) и `CHANGELOG.md`, и делать `git commit` после каждого шага. Тогда следующая передача контекста займёт один файл.
7. **Небольшие файлы (до ~300 строк) надёжнее заменять целиком** (`REPLACE`), чем хрупкими якорями.
8. **Просите конкретные данные сразу:** строки `gen …`, текст ошибки, скриншот инспектора из вкладки Remote. Расплывчатое описание стоило нам лишних итераций.
9. **Лекции о теории — только по запросу.** Пользователь ценит конкретику и быстрый результат.

**Ближайшее действие для преемника:** спросить у пользователя результат RECOVER (строки `gen` на ~100 и ~400 поколении и поведение после пробуждения с `ARB ROM`) и подтвердить, что три уровня боли ведут себя как задумано.
