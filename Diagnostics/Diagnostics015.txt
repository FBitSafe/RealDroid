Fix020 — Diagnostics report
===========================

## 1. CP-step OFF by default (game and dream)

Ожидалось:
- MotorRom `CapturePointStepping` и NeuralMotorChip `BaseStepping` по умолчанию false,
  код шага не удаляется.
- Dream: шаг выключен, новый `--cp-step` включает, `--no-cp-step` остаётся и ничего не
  ломает; стартовый лог `MOTOR ROM capture-point stepping: OFF (RECOVER v1)` или
  `100% (no fade)` при `--cp-step`; в строках `gen` писать `CP step off` при выключенном шаге.
- `--motor-rom-step-test` работает и без шага (тест «голеностоп + бёдра»).
- Main: клавиша C по-прежнему переключает шаг, начальное состояние выключено и видно на панели.

Найдено:
- `Chips/MotorRom.cs`: `public bool CapturePointStepping = true;`
- `Chips/NeuralMotorChip.cs`: `public bool BaseStepping = true;`
- `Dream/Dream.cs`: флаг `_disableCapturePointStepping`, `MakeRun` превращал его в
  `BaseStepping = !_disableCapturePointStepping` и `BaseStepAssist`;
  в `EndGeneration` строка `CP step {stepAssist:P0}`.
- `Dream/Dream.Args.cs`: был только `--no-cp-step`.

Сделано:
- `MotorRom.CapturePointStepping` → `= false`.
- `NeuralMotorChip.BaseStepping` → `= false`.
- `Dream/Dream.cs`: флаг переделан в `_cpStepEnabled` (по умолчанию false).
  - `MakeRun`: `BaseStepping = _cpStepEnabled; BaseStepAssist = _cpStepEnabled ? CapturePointAssistForGeneration() : 0f;`
  - в протокольном тесте: `new MotorRom { CapturePointStepping = _cpStepEnabled }`.
  - стартовый лог: `!_cpStepEnabled ? "OFF (RECOVER v1)" : CpStepFadeGenerations <= 0 ? "100% (no fade)" : ...`.
  - в `gen`: `_cpStepEnabled ? $"CP step {stepAssist:P0}" : "CP step off"`.
- `Dream/Dream.Args.cs`: добавлен `--cp-step` → `_cpStepEnabled = true`;
  `--no-cp-step` → `_cpStepEnabled = false` (backward-compatible, но это значение и есть дефолт).
- Main: клавиша C не менялась, но из-за дефолта false теперь стартует с выключенным шагом;
  на панели строка показывает `шаг: выкл`.

ArbiterRom без шага выходит из RECOVER в STAND:
- Да, подтверждено. При выключенном CP-шаге MotorRom не разводит стопы, поэтому условие
  выхода из RECOVER (`spread <= ExitSpread` и обе стопы на земле, `|ComVx| <= ExitVel`,
  запас `m > ExitMargin`, `_exitDwell >= ExitDwell`) выполняется сразу после возврата ξ в опору.
  В выводах тестов 1 и 4 все экзамены показывают `recover≈0.60s`, `СТОИТ`, шаг вывода `шаг=0px/1px`.

## 3. Сила толчка в игре в процентах

Найдено в `RecoverEpisode`:
`_imp = (_dir == 0 ? 1f : -1f) * t.LevelOf(_dir) * t.PushMax;`
и применение `g.Bodies[g.Chest].ApplyCentralImpulse(new Vector2(_imp, 0f));`
(`PushMax = 3000f`).

Сделано:
- Новый `Core/PushModel.cs`: `PushModel.FullImpulse = 3000f`;
  `PushModel.Impulse(float level, int dir, Ragdoll body)` применяет в грудь
  `(dir == 0 ? +1 : -1) * level * FullImpulse`; `dir 0 = в спину (+x)`, `dir 1 = в грудь (−x)`.
- `RecoverTask.PushMax` = `PushModel.FullImpulse` (число не изменилось).
- `RecoverEpisode.Step` использует `PushModel.Impulse(...)` для первого и второго толчка.
- `Main` использует `PushModel.Impulse(PushLevel, dir, _girl)` для Q/E.
- Main: `float PushLevel = 0.45f`; клавиши `[` и `]` меняют на ±0.05 в пределах 0.05..1.0.
  Q = толчок в грудь (−x), E = толчок в спину (+x) — те же стороны и та же точка (грудь), что во сне.
- `BrainPanel` рисует строку:
  `толчок 45% [ ]  Q=грудь E=спина  шаг: выкл`
  (процент считается `RoundToInt(clamp(PushLevel, 0.05, 1) * 100)`, состояние шага читается
  из MOTOR ROM/NN в текущем слоте).
